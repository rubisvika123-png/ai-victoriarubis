# Монтаж рилса — рецепт, который работает

Это набор монтажёра автора курса: на нём каждый день монтируются её рилсы. Правила ниже
не теория — каждое появилось после конкретного брака. Не придумывай своё оформление:
шрифт, цвета, плашку, подсветку слов, кодовое слово берёт `build_ass.py` из `style.json`.

Пути: `RM=/root/reels-montage` (набор), `JOB=` папка задания (например `/root/video-jobs/reel-ДАТА`).
Ставится один раз: `bash <папка агента>/skills/reels-montage/install.sh`.

## 0. Стиль владельца — один раз
Если в `$RM/style.json` пустое `code_word` и владелец ещё не подтверждал стиль — спроси коротко:
фирменные цвета (2–3, можно словами — переведи в #RRGGBB), кодовое слово для комментариев,
устраивает ли скорость 1,15×. Запиши в `$RM/style.json`. Больше эти вопросы не задавай.

## 1. До монтажа — ТРИ хука на выбор
Сначала расшифруй речь (шаг 4) и предложи владельцу 3 варианта хука: капслок, 2 строки,
до ~6 слов в строке, словами из самого ролика. Ключевые слова, которые красить, — пометь.
Монтируй только после выбора. Хук — это ПЛАШКА сверху поверх живого видео, не субтитр.
Если владелец сам дал текст хука — бери его дословно и сразу монтируй.

## 2. Задание
```bash
mkdir -p $JOB/work   # куски видео: $JOB/part1.mov, part2.mov, … по порядку
```
Составь список всех присланных кусков, проверь каждый (`ffprobe`). Все части обязательны.
Порядок для трёх частей: голова → показ экрана → голова с призывом.

## 3. Нарезка каждого куска — паузы и дубли ВЫРЕЗАЮТСЯ
```bash
for i in 1 2 3; do $RM/roughcut.sh $JOB/part$i.mov --dry-run; done     # список фраз и дублей
for i in 1 2 3; do $RM/roughcut.sh $JOB/part$i.mov --speed 1.0 --crf 14 --seams $JOB/work/seams$i -o $JOB/work/clean$i.mp4; done
```
Неудачный дубль — `--drop ОТ-ДО` по списку из `--dry-run`. **Повтор фразы и ложное начало вырезаешь сам,
не спрашивая** («и после этого его… и после этого его» — остаётся последний чистый вариант): владелец
снимает «если сбилась — скажи заново», лишний заход в ролике — брак. Режь по звуку, а не по таймкодам
расшифровки. Запрещено `--silence speed` для куска целиком: ускоренная пауза видна как «перемотка».
iPhone HDR сначала переводи в SDR, потом режь. Посмотри кадры на швах: скачка позы быть не должно.

## 4. Склейка, тишина на стыках, скорость, 1080×1920, расшифровка
Тишину в начале и конце каждого `clean$i.mp4`: `ffmpeg -i clean$i.mp4 -af silencedetect=n=-40dB:d=0.12 -f null -`
(начало = конец первой тишины, конец = начало последней тишины **+ 0,15 с**). Конец фразы часто тихий —
без запаса режется последнее слово, и ролик уходит на следующий кусок, пока человек ещё договаривает.
**Хвост каждого куска проверь до склейки:** в списке фраз `--dry-run` последнее слово куска должно звучать
в `clean$i.mp4` целиком (`ffmpeg -sseof -2 -i clean$i.mp4 tail$i.wav` и расшифровка). Вытащи кадры последних
0,5 с: увод камеры или опущенный телефон режь до первого плохого кадра, но не раньше конца последнего слова. Затем (для 3 кусков; другое число — столько же входов):
```bash
cd $JOB/work && ffmpeg -v error -y -i clean1.mp4 -i clean2.mp4 -i clean3.mp4 -filter_complex \
"[0:v]trim=S1:E1,setpts=PTS-STARTPTS,fps=30,scale=720:1280,setsar=1[v0];[0:a]atrim=S1:E1,asetpts=PTS-STARTPTS[a0];\
[1:v]trim=S2:E2,setpts=PTS-STARTPTS,fps=30,scale=720:1280,setsar=1[v1];[1:a]atrim=S2:E2,asetpts=PTS-STARTPTS[a1];\
[2:v]trim=S3:E3,setpts=PTS-STARTPTS,fps=30,scale=720:1280,setsar=1[v2];[2:a]atrim=S3:E3,asetpts=PTS-STARTPTS[a2];\
[v0][a0][v1][a1][v2][a2]concat=n=3:v=1:a=1[v][a]" -map "[v]" -map "[a]" -c:v libx264 -crf 14 -preset slow -pix_fmt yuv420p -c:a aac -b:a 192k -ar 48000 joined.mp4 \
&& ffmpeg -v error -y -i joined.mp4 -filter_complex "[0:v]setpts=PTS/1.15,scale=1080:1920:flags=lanczos,setsar=1[v];[0:a]atempo=1.15[a]" \
-map "[v]" -map "[a]" -c:v libx264 -crf 16 -preset slow -pix_fmt yuv420p -r 30 -c:a aac -b:a 192k -ar 48000 base.mp4 \
&& ffmpeg -v error -y -i base.mp4 -map 0:a -ac 1 -ar 16000 -c:a pcm_s16le ab.wav
cd $RM && ./gigaam-venv/bin/python tools/transcribe_chunks.py $JOB/work/ab.wav $JOB/work/tb.json ТОЧКИ
```
1,15 — скорость из `style.json` (`speed`). ТОЧКИ — секунды разрезов звука для GigaAM, в паузах между
фразами, примерно каждые 13–15 с (`14.5,28.0,41.5`). Финал всегда 1080×1920.

## 5. Где стоят тексты — мерить по лицу, не из памяти
```bash
$RM/venv/bin/python $RM/tools/text_zones.py $JOB/work/base.mp4 --to 6    # для хука
$RM/venv/bin/python $RM/tools/text_zones.py $JOB/work/base.mp4           # для субтитров
```
Хук не на лбу, субтитры не на подбородке. `hook_y` — из первого замера.
**Субтитры — низко:** `sub_y` = большее из двух чисел: 1400 (утверждённая высота автора — ниже груди,
выше подписи Reels) и `sub_y` второго замера (ниже подбородка), но не больше 1490. Пример: замер дал 1206 —
ставишь 1400. Субтитры, задранные к лицу, автор браковала.
`hook_fits: false` / `sub_fits: false` — места нет: спроси владельца, не ставь наугад.

## 6. job.json этого ролика
```json
{"hook": "ПЕРВАЯ СТРОКА|ВТОРАЯ СТРОКА", "hook_keys": ["ВТОРАЯ СТРОКА"], "hook_end": 4.0,
 "hook_y": 270, "sub_y": 1400, "phrases": [[["и","агент"], "ИИ-АГЕНТ"]], "replace": {"тред": "THREADS"}}
```
Пройди `work/tb.json` целиком и добавь в `phrases`/`replace` всё, что распознаватель услышал неверно
(бренды латиницей, «ИИ» вместо «и-и-и»). Одной «И» вместо «ИИ» в субтитрах быть не должно.
Правишь только то, что распознаватель **услышал неверно**. Слова, которые человек сказал, не меняешь
(«пять» не превращается в «пятницу», «маркетологов» — в «маркетолог»).

## 7. Сборка
```bash
$RM/venv/bin/python $RM/tools/build_ass.py $JOB && cd $JOB && ffmpeg -v error -y -i work/base.mp4 \
-vf "ass=subs.ass:fontsdir=$RM/tools/fonts" -af "loudnorm=I=-16:TP=-1.5:LRA=11" \
-c:v libx264 -crf 22 -preset slow -pix_fmt yuv420p -colorspace bt709 -c:a aac -b:a 160k -ar 48000 -movflags +faststart final.mp4
```
Файл для Telegram — до 45 МБ (больше — `-crf 24`).

## 8. Приёмка — до слова «готово», без исключений
1. `$RM/venv/bin/python $RM/tools/check_reel.py $JOB/final.mp4` → должно быть «ПРИНЯТО». «БРАК» — не отправлять.
2. Вытащи 3 кадра ИЗ ФАЙЛА, КОТОРЫЙ ОТПРАВЛЯЕШЬ (момент хука, середина, кодовое слово) и посмотри
   на них сам: хук — плашка сверху, не на лице; субтитры ниже подбородка; лицо видно с первого кадра.
3. Начало: ролик стартует с речи и движения, без застывшего кадра и тишины.
   Стыки: каждый кусок договорён до конца — последнее слово перед стыком звучит целиком.
4. Не посмотрел кадры финала — не пиши «готово» и «исправил». Отчёт без просмотра — неправда.
5. Владельцу — коротко, что в ролике, и сам файл. Промежуточные версии не шлёшь.

## Жёсткие правила оформления
- 9:16, видео на весь кадр, без полей и размытой подложки. Цвет исходника не трогать.
- Субтитры — всегда внизу, в одной неподвижной полосе, капслок, 2–4 слова, сказанное белым,
  следующее серым. Никогда не наверх и не вместо хука. Без тёмной плашки под ними.
- Точка, «!» или «?» внутри блока — брак (конец предложения закрывает блок — это делает build_ass.py).
- Частица «не» никогда не остаётся последней в блоке — отрицание держится со своим глаголом.
- Хук крупнее субтитров, сверху, поверх живого видео. Никогда — чёрная заставка вместо лица.
- Кодовое слово — только из речи владельца, крупно и отдельно вверху кадра на каждом призыве.
- Весь важный текст — в безопасной зоне Reels: для 1080×1920 x=65–950, y=270–1248.
- Громкость около −16 LUFS, пик не выше −1 dBFS. H.264, BT.709, AAC 48 кГц.
- Правку оформления вноси в `job.json`/`style.json`, а не разовой командой: разовая правка теряется
  при следующей сборке.
