# ИИ-секретарь в личном Телеграме владельца (Telegram для бизнеса)

Эта инструкция — **для агента-техспеца (Claude Code)**, а не для владельца.
Владелец даёт команду «поставь мне ИИ-секретаря по docs/business-secretary-runbook.md»,
ты выполняешь шаги сверху вниз и после каждого коротко, простыми словами, говоришь
владельцу, что сделано.

Что получится: клиенты пишут владельцу в его **личный** Телеграм, а отвечает им
секретарь — от имени владельца, с его аватаркой. Отвечает только по базе знаний,
которую дал владелец. Всё, чего нет в базе (запись на время, скидки, жалобы), он
передаёт владельцу уведомлением, а клиенту пишет «уточню и вернусь».

Всё ниже выполняется на сервере от `root`.

## Чего НЕ делать (важно)

- **Никогда не подключайся к личному аккаунту владельца по коду входа** (Telethon,
  Pyrogram, «юзербот», my.telegram.org). Телеграм отменяет код, если его переслать
  сообщением, — получится бесконечный круг. И так можно потерять аккаунт: Телеграм
  замораживает аккаунты, которыми управляет программа с сервера. Единственный
  правильный путь — этот: официальная функция «Telegram для бизнеса».
- **Не давай секретарю никаких инструментов и не подключай его к себе.** Ему пишут
  чужие люди. Скрипт запускает Claude с выключенными инструментами
  (`--tools ""`), без MCP, без настроек и в пустой папке — так любое «удали всё»
  от клиента остаётся просто текстом. Эти флаги не убирать.
- **Не используй для секретаря бота техспеца.** У секретаря свой отдельный бот.

## Шаг 0. Что владелец делает руками

Это делает только владелец, в своём Телеграме. Скажи ему одним сообщением и жди:

1. Нужен **Telegram Premium** на его аккаунте. Без Premium Телеграм не даёт
   подключить бота к личным чатам.
2. Новый бот: в `@BotFather` → `/newbot` → имя и адрес (адрес заканчивается на
   `bot`) → прислать тебе токен вида `8123456789:AAF...`.
3. Включить боту режим секретаря и подключить его к своему Телеграму — по шагам
   из урока «Готовый навык: ИИ-секретарь». Сначала **только один тестовый чат**.
4. Написать тебе, что секретарь должен знать: услуги, цены, адрес, часы работы,
   как записаться, частые вопросы.

## Шаг 1. Папка, база знаний и настройки

```
mkdir -p /root/business-secretary/state && chmod 700 /root/business-secretary
```

Запиши то, что прислал владелец, в `/root/business-secretary/knowledge.md`
простым текстом. Только факты владельца — ничего не додумывай.

Номер владельца в Телеграме возьми из `secrets/channel.env` (первое число в
`TELEGRAM_ALLOWED_USER_IDS`). Создай `/root/business-secretary/secretary.env`
(права 600), токен — тот, что прислал владелец:

```
SECRETARY_BOT_TOKEN=<токен нового бота>
SECRETARY_OWNER_ID=<номер владельца>
SECRETARY_KNOWLEDGE=/root/business-secretary/knowledge.md
SECRETARY_STATE_DIR=/root/business-secretary/state
SECRETARY_MODEL=sonnet
```

Модель `sonnet` — чтобы секретарь не съедал общий лимит подписки Claude, на
которой работают все агенты. Не меняй без слова владельца.

Проверь бота (токен в вывод не печатай):

```
set -a; . /root/business-secretary/secretary.env; set +a
curl -s "https://api.telegram.org/bot${SECRETARY_BOT_TOKEN}/getMe" | grep -o '"can_connect_to_business":[a-z]*'
```

Должно быть `"can_connect_to_business":true`. Если `false` — владелец ещё не
включил боту режим секретаря в BotFather.

## Шаг 2. Проверка скрипта

Скрипт лежит в твоей папке: `scripts/business-secretary.py`. Если его нет —
обнови папку из заготовки курса (репозиторий `rubisvika123-png/ai-victoriarubis`).

```
python3 scripts/test_business_secretary.py
```

Должно напечатать `PASS`.

## Шаг 3. Служба, чтобы секретарь работал всегда

Узнай полный путь к своей папке (`pwd`) и к `claude` (`command -v claude`).
Создай `/etc/systemd/system/business-secretary.service`, подставив пути:

```
[Unit]
Description=Business secretary (Telegram для бизнеса)
After=network-online.target
Wants=network-online.target

[Service]
EnvironmentFile=/root/business-secretary/secretary.env
Environment=HOME=/root
Environment=PATH=<папка, где лежит claude>:/usr/local/bin:/usr/bin:/bin
WorkingDirectory=/tmp
ExecStart=/usr/bin/python3 -u <твоя папка>/scripts/business-secretary.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

`HOME` обязателен: без него Claude не найдёт свой вход в аккаунт.

```
systemctl daemon-reload && systemctl enable --now business-secretary
systemctl status business-secretary --no-pager | head -5
```

## Шаг 4. Уведомления владельцу

Попроси владельца открыть своего нового бота и нажать **Start** (Запустить).
Иначе бот не сможет присылать ему «клиент ждёт твоего ответа».

## Шаг 5. Проверка на одном тестовом чате

Владелец просит знакомого написать ему в личку вопрос из базы знаний (например,
«сколько стоит…»). Смотри журнал:

```
journalctl -u business-secretary -n 20 --no-pager
```

Должны быть строки `msg chat=...`, `model answer ...`, `sent ... ok=True`, а у
знакомого — ответ от имени владельца. Потом попроси знакомого написать
«можно записаться на завтра?» — клиенту придёт «уточню и вернусь», а владельцу
уведомление от бота.

Важно: если владелец сам что-то напишет в этот чат, секретарь замолкает в нём на
12 часов (чтобы не перебивать владельца). Так и задумано.

## Шаг 6. Включить для клиентов

Когда тест прошёл, владелец меняет в Телеграме список чатов с одного тестового на
новых людей, которых нет в контактах, — по уроку. Друзья и семья из контактов
остаются без бота.

## Как управлять потом

- **Поменять, что знает секретарь:** поправь `knowledge.md`. Перезапуск не нужен,
  файл читается на каждое сообщение.
- **Выключить быстро:** владелец сам отключает бота в настройках Телеграма, или
  `systemctl stop business-secretary`.
- **Секретарь молчит:** `journalctl -u business-secretary -n 50 --no-pager`.
  `model failed` — проблема с Claude (лимит, вход). Строк `msg chat=` нет вообще —
  бот не подключён в Телеграме или выбран не тот чат.
- **Отвечает только на текст.** Голосовые, фото и файлы он не разбирает, а
  присылает владельцу уведомление «ответь сам».
- После перезапуска на сообщения старше 5 минут не отвечает — чтобы не завалить
  людей запоздалыми ответами.
